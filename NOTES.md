### NOTES.md

The optimal configuration was achieved in Experiment 4, utilizing a 4-layer, 192-dimension architecture with a peak learning rate of 1e-3. The Pre-LN RMSNorm architecture, paired with weight tying and SwiGLU activations, provided the most stable gradient flow for the 2,000-step speedrun budget. Expanding the context block size to 256 was the primary driver of performance, allowing the model to capture significantly more linguistic dependency than the baseline 128 tokens. Experiment 5 confirmed that adding dropout to a small 7MB dataset hinders convergence, proving that 0.0 dropout is optimal for this specific corpus. Experiment 6 attempted to use a custom Byte-Pair Encoding (BPE) tokenizer to compress Hindi characters, but the expanded vocabulary size introduced too many new, untrained parameters to optimize effectively within 2,000 steps, leading to a regression in compression efficiency. The high learning rate of 1e-3 was critical, ensuring the optimizer traversed the loss landscape aggressively and efficiently. Weight tying between the input embeddings and output head successfully funded the larger model dimensions while keeping the total parameter count at 1,820,352, well below the 2,000,000 cap. This configuration represents the optimal balance of architectural depth, context window size, and optimization velocity for this corpus.
