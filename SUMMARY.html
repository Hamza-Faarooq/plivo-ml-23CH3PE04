Research Summary: LLM Speedrun Optimization

1. Executive Summary

This report documents the optimization of a GPT-style language model constrained to 2M parameters and 2,000 training steps. The primary goal was to minimize the Bits Per Byte (bpb) metric on a held-out mixed-language (English/Hindi) corpus. By implementing architectural upgrades—specifically SwiGLU, RMSNorm, and Rotary Positional Embeddings—and tuning the learning rate schedule, I achieved a final bpb of 1.9094.

2. Architectural Specifications ("Nodes")

The model architecture was rebuilt to maximize parameter efficiency while strictly adhering to the 2,000,000 parameter hard cap[cite: 6].

  • RMSNorm: Replaced LayerNorm to normalize hidden states, providing faster execution and improved training stability.
  • Rotary Positional Embeddings (RoPE): Replaced absolute position embeddings. RoPE allows the model to better manage relative positions, crucial for the complex sequence structures found in mixed-script text[cite: 6].
  • SwiGLU Activation: Replaced the standard GELU layer. SwiGLU provides non-linearities that lead to more efficient information compression per parameter[cite: 6].
  • Weight Tying: Linked input embeddings and output projection weights, reclaiming significant parameter budget, which allowed for a wider (160 dim) hidden state and deeper network depth (5 layers).

4. Metric Justification: Why Bits Per Byte (bpb)?

Bits Per Byte is the optimal metric for this task because it provides a hardware-agnostic, lossy-compression-invariant measure of how much information the model has learned about the text distribution. Unlike raw Cross-Entropy loss, which is tokenization-dependent, bpb normalizes the compression rate against the raw byte-stream of the data. This makes it the most robust metric for comparing the efficiency of different tokenization strategies, as it directly reflects how well the model "compresses" the language into its parameters[cite: 6].
